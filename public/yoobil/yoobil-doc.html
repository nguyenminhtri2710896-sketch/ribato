API Encryption Rules

Key Pair Generation Method

Due to the various formats of RSA keys, the payment system currently supports only PKCS8 key pairs with a length of 2048. The key formats obtained from different channels may not be the same, and may not meet the key pair requirements of the payment system. In order to ensure that all merchants can obtain key pairs that can be used in the payment system, we provide the following way to obtain key pairs. Merchants can use the following commands on Mac/Linux using OpenSSL to generate available key pairs:
Private key generation:

openssl genpkey -out rsa_private_key.pem -outform PEM -algorithm RSA -pkeyopt rsa_keygen_bits:2048

Public key generation:

openssl rsa -in rsa_private_key.pem -pubout -out rsa_public_key.pem

Encryption Rules

To ensure the security of transactions, this system uses an encryption mechanism for all interactive APIs, and this set of encryption rules must be used for all API interactions to ensure the security of partner funds. The encryption rules are as follows:
According to the specific API document, obtain the required request parameter list and form a Map in the form of key-value pairs (key=value).
The calculation process of the "sign" parameter is as follows:
a. Sort the key-value pairs in Map1 by key in ascending order according to ASCII code to generate the key-value pairs Map2.
b. Connect the ordered parameter key-value pairs in Map2 with "&" to form String1.
c. Append the secret key to the end of String1 to generate String2.
d. Sign String2 with your private key using the SHA256withRSA algorithm and then Base64 encode it (no need for UrlSafe Base64 at this time). This value is the value of the "sign" parameter.
e. Insert the generated "sign" as a key-value pair <sign,"xxxxx"> into the request parameter Map. This completes the encapsulation of the request parameters.
For GET requests, connect the request parameters with "&" and then Base64 encode the concatenated result using URL-safe Base64 to generate the "param" parameter. Finally, use the "param" parameter to initiate a request to the payment system API:
GET https://domain.com/apidemo?param=xxxxxxx
For POST requests, use the Map parameters that have been encapsulated as a JSON format for the Post body and initiate the Post request directly.

Verify the signature of the result returned by the payment system.

All callbacks from the payment system are sent using the POST method.

  1. Parse the data returned by the payment system API, usually in JSON format, and extract the "code" and "result" fields from the outermost layer of the JSON. If the "code" is not 10000 or the "result" is empty, there is no need to verify the signature.
  2. Parse all key-value pairs in the "result" field, extract the "sign" field and save it, and then remove any fields that are marked as not requiring signature verification in the API documentation.
  3. Repeat the steps 1, 2, and 3 of calculating the "sign" for the request, and use the public key downloaded from the payment system to verify the signature using SHA256withRSA.
